# Requirements traceability matrix — Meridian UAV Services

**Written for:** a reviewer checking that every stated requirement is implemented somewhere specific
and tested by something that can fail.

> **Data disclosure.** Meridian UAV Services is a fictional UAV operator. All data is synthetic and
> generated by the scripts in `sql/`. No confidential data is used and no claim is made about any
> production system.

---

## How to read this

Each requirement names **where it is implemented** and **what would catch it breaking**. The last
column is the one that matters: a requirement whose test is "it looks right on the dashboard" is not
traced, it is asserted.

Where a test is a UAT case, the case asserts a **value**, not a property. `compliance is between 0
and 100` holds under every transformation that preserves it, including the bug it was written for.

## B. The modelling decisions

| ID | Requirement | Implemented in | Verified by |
|---|---|---|---|
| **MD-01** | Wear is measured in stress-weighted duty cycles, not flight hours | `Ref_StressModel`, `vw_SortieStress` | UAT-05 asserts the three stress terms sum to the total on **every** row |
| **MD-02** | The stress model is contestable reference data, not logic buried in a query | `Ref_StressModel` with `SourceNote` per row | Exported as `ref_stress_model.csv` and shown on the Power BI / Streamlit reference screens |
| **MD-03** | Accrued component life is a dated fact computed in a window, never an attribute stored on the row | `fn_ComponentWear`, `vw_ComponentLifeHistory` | UAT-08 reconciles against a second computation straight off `Fact_Sortie` |
| **MD-04** | A sortie belongs to the component that was fitted for it, not to its replacement | `EffectiveStartDate` in `fn_ComponentWear` and `vw_ComponentLifeHistory` | UAT-31; creation gate 53025 |
| **MD-05** | Fleet membership is a date question, never a current-status attribute | `IsInFleetAsOf` in `fn_ComponentWear` and `fn_AirframeStress` | UAT-29 asserts fleet size differs between dates; UAT-30 asserts the *denominator* moves |
| **MD-06** | The service interval is expressed in both units so the two can be compared | `Ref_ServiceInterval` carries both columns | UAT-13 |
| **MD-07** | A scheduled removal is censored, not a failure | `vw_ComponentLifeHistory.IsCensored` | Used by `python/degradation_model.py`; a life with no failure is a negative, never a positive |
| **MD-08** | A component life with impossible dates is reported but never scored | `vw_ComponentLifeHistory.IsDateValid`, filtered in `fn_AlertEvaluation` | UAT-33 asserts kept 6, scored 0 |
| **MD-09** | Reporting settings are pinned in a table, not derived from the data | `Ref_Reporting` | Every procedure resolves through `fn_ReportingDate` / `fn_ReportingDecimal` and raises on NULL |

## C. The as-of discipline

## D. Prediction quality
